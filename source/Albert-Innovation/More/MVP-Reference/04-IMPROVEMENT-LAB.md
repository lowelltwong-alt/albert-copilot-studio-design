# Start your own improvement process

Treat the saved outputs as evidence. This kit is useful because you can see where an attempt fails, make one focused change and test whether the next attempt improves. It does not learn or install revised prompts automatically.

## First experiment

1. Complete the supplied short case with the unchanged starter. Save every first-pass artifact and both independent reviews. This is your baseline; label held outputs as held.
2. Choose one observed defect, such as missing a supported conflict, lecture-like exchanges, a recall prompt after the pause, or an edit that deletes teaching. Use [RUN-11](prompts/RUN-11-AUDIT.md) in a fresh non-author review context and [the experiment template](templates/EXPERIMENT.md). Inspect the source of the defect before changing a prompt: missing input, bad permission view, inadequate model/context, vague instruction, execution failure or reviewer error are different causes.
3. Make one minimal candidate change in a new local version. Record the exact before/after wording, why it should help, affected stages and a counterexample. Keep the prior package. Do not edit the embedded historical reference files and reuse their original receipt.
4. Run the same fixed input through baseline and candidate with the same chosen model/settings and declared context. Review the complete outputs without the writer's numeric self-score. Record source/permission/method holds separately from five craft dimensions (0–4): host contribution, useful depth, examination practice, taught-and-retrieved anchors, and listening coherence. Preserve the original judge scores, disagreement and concrete evidence.
5. A second development loop is optional only after a material benefit with no new source/permission/method error, no craft regression and a named remaining deficit. Use the inherited P09 rule: mean gain at least 2/20 across two target-masked paired judgments, or a verified material source repair without craft regression. Same-model judges remain a limitation. Stop at two development loops, plateau, regression or unresolved disagreement. Ordinary case production still gets at most one verified repair plus full recheck.
6. Freeze the candidate before a fresh run. Give new authors the prompts and source packet, not old answers, plans, grades or case-specific repair notes. Test another witness and then another case type. Record first-pass and repaired outcomes separately. Adopt locally only after the owner reviews those results; otherwise retain the candidate as an experiment.

## The highest-value next tests

| Observed weakness | Focused change to try | Evidence that would count |
|---|---|---|
| Thin explanation despite a good plan | Draft and inspect one developed pressure module before expanding the episode | Actual source-grounded exchange, consequence, supported question, response opportunity and feedback survive the full assembly |
| Lecture with alternating labels | Ask the second host to challenge a specific tempting inference | Removing that host's turn would lose a real distinction; a reviewer cites the exchange |
| Card says ten anchors but audio never teaches them | Require an as-built taught/asked/paused/feedback map for every card clause | Each clause is taught before retrieval; a keyword match alone does not pass |
| Repair removes useful material | Limit the edit to verified locations; preserve all unaffected payoffs | Before/after review verifies repaired and preserved content, including repeated occurrences |
| Reviewer gives a false pass | Audit instructions against its actual evidence and report | Independent reproduction identifies reviewer_error; another case probe catches the same weakness |

The inherited T07 semantic-anchor work remains an unqualified later candidate. Its idea informs the clause-level inspection above, but this kit does not claim T07 was fully passed or silently installed in the shared core.

Keep generic lessons in a small searchable list: lesson ID, trigger, failed input/output references, proposed instruction, acceptance probe, rejection probe, owner and candidate/adopted/rejected status. Keep case facts in the authorized case folder. A generic lesson must not contain a witness's private testimony. See [limitations](05-LIMITATIONS-AND-ROADMAP.md) for the actual study results.
